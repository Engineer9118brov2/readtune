For school technology administrators

ReadTune in a managed environment

ReadTune is a free reading-accessibility extension. It collects no student information and stores its settings locally on the device. One optional feature, Ask AI, sends text to a relay only when a student chooses to use it — disclosed in full below. This page is for the person deciding whether to add it to an allow-list.

The short version. No accounts, ever. No analytics or telemetry, anywhere. Reading profile, calibration history, and highlights never leave the device. The one exception: if a student turns on Ask AI and types a question, that question and the article text go to ReadTune's relay to generate an answer — nothing else does, and nothing happens automatically. Installs with activeTab, scripting, and storage only. No cost, no licence, no renewal. Works offline except for that one opt-in feature.

Student data

ReadTune does not collect, store, or transmit any personally identifiable information. It requires no login, no email, and no account of any kind. A student's reading profile, calibration history, reading position, and highlights are written to the browser's local extension storage (chrome.storage.local) on that device and are never sent anywhere.

The one exception is Ask AI (see "Network behaviour" below): if a student types a question about an article, that question and the article text are sent to ReadTune's relay to generate an answer. It is off unless a student opens it and asks something — nothing is sent automatically, and the relay keeps no record of who asked. We'd rather a school district see this stated plainly than discover it later, so treat Ask AI as the one part of ReadTune to evaluate against your own AI-in-the-classroom policy before enabling it district-wide; everything else has nothing for COPPA or FERPA to attach to, and we'll put that in writing on request.

Network behaviour

Read-aloud uses Piper, a neural voice that runs entirely on the device. The default voice ships inside the extension, so it works offline with nothing to download and the reading text is never uploaded. If a student picks one of the optional voices in the Reading Lab, that one model file downloads once from Hugging Face and is then cached on the device. Page reformatting, PDF text extraction, and the calibration test all run entirely in the browser using code bundled in the extension (no CDN, no remote scripts — Manifest V3 forbids them and ReadTune loads none).

Ask AI (opt-in, the one feature to evaluate): Reader View has an "Ask AI" panel where a student can request a summary or type a question about the article they're reading. If they do, the article text — and, for a typed question, the question itself — is sent to ReadTune's own relay (readtune.tech/api/assist), which forwards it to a third-party AI model to generate the response. This is off unless a student opens the panel and asks; it never runs automatically. The relay does not log who asked or keep any account trail; it may cache a generated answer by the article's URL (and question) purely so a popular article isn't re-processed on every request. Treat this the way you would any AI tool against your district's policy — everything else on this page is unaffected either way.

One further opt-in exception: a student can paste their own ElevenLabs API key to use higher-quality read-aloud voices. If they do, the passage being read and their key are sent to api.elevenlabs.io to generate audio. This requires a personal ElevenLabs account and API key, which students on a school account will not have, and it can be disregarded for your evaluation. The feature is off by default and there is no ElevenLabs integration unless a key is entered.

Support burden

  • ~60 MB download, almost all of which is the bundled public-domain voice that lets read-aloud work offline. The extension code itself is a couple of MB. Optional extra voices download once per reader and can be skipped entirely.
  • Nothing to configure centrally. A student runs the 4-minute calibration once; everything else is a preference.
  • Open source — the full code is on GitHub for your security team to inspect before approval.
  • The extension is inert on chrome:// pages and the Chrome Web Store, like all extensions.

How to allow ReadTune (Google Admin console)

Devices → Chrome → Apps & extensions → Users & browsers
→ select the organizational unit
→ "＋" → Add Chrome app or extension by ID
→ paste the ReadTune extension ID
→ set to "Allow install" (or "Force install" for a class set)

Cost

Free. There is no paid tier, no per-seat pricing, no quote, and no upsell inside the product. Every feature — including the text-to-speech and the calibration test — is available to every student at no cost to the district.
